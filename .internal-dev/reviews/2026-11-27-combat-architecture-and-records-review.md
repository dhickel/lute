# Combat enhancement architecture and records review

## Scope
Baseline `7d2cc902fad167d814dbfe0b8e00dc160c6731c9`. Four senior reviews covered gameplay/AI/arena, data/assets/editor/build, engine lifecycle and structure, and living documentation/records. Static review; line references are to the inspected baseline. Ignored assets are pack-local. No game code changed or runtime tests run for this audit.

## Risk Assessment
The main growth is duplicated ownership, not a need for new frameworks. Keep `AttackAnimKey`, AI's slot selection, the separate unscored Test Area, ordered physics/contact handling, the intentional ECS schedule, and strict validation at boundaries. Do not turn procedural moves, fixed-step policies, atlas invariants, or test-only scenario literals into general configuration. The present `iron_arrow` limitation does not justify an ammo abstraction without a requirement. `stats.cost` is accepted but unused in combat; hit sounds are intentionally loaded but not played. Neither should be removed without considering the schema contract.

## Recommendations
1. Fix rollback ownership, tile placement, and the authoring test/editor feedback loop before large refactors.
2. Remove the Dredge loadout override and simplify the arena/combat boundary without shifting timing. Record scoring rollover separately.
3. Prune verified redundancy: empty private `GameCore.input`/`logic`, commented physics loop, write-only `Transform.sortOffsetY` field (not a constructor API change), duplicate active-attack state and redundant lunge-specific controller switch guard. Reference searches found only declarations for `Combat.setAttackFacing`, `Action.flee` and `Action.multiAction` in searched Java sources; treat removals as a separate scoped change. Do not remove `mountedCombat`, which is a live Ashley family-removal fallback, or the separate map sensor drain, which has direct test coverage.
