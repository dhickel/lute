# Desktop bundles select Java 21 for Java 25 bytecode

## Summary
P1 for bundled desktop distribution: all Construo targets select JDK 21 downloads while application compilation targets Java 25.

## Scope
Root `build.gradle` Java toolchain/source/target settings; `lwjgl3/build.gradle` release setting and Construo jdkUrl values for Linux x64, macOS ARM/x64 and Windows x64.

## Reproduction
Build a configured bundled desktop distribution and launch it using its selected Java 21 runtime. The application class files require Java 25.

## Expected
A packaged runtime supports the bytecode emitted by the configured compiler.

## Actual
Java compilation uses release 25, while all four bundled runtime URLs reference Temurin 21. Java 21 cannot load Java 25 class files.

## Evidence
Independent `javap -verbose` inspection of Lwjgl3Launcher.class in the isolated audit build reports major version 69 (Java 25); Java 21 supports major version 65. All configured runtime URLs explicitly select 21.0.10. Packaging/download and launch were not performed; this finding is established by incompatible configured versions and generated bytecode.

## Impact
Configured runtime bundles cannot execute the application. Local Gradle execution using JDK 25 is not affected.

## Status
Open; source and bytecode confirmed. GitHub: https://github.com/dhickel/lute/issues/18 (open; related closed issues checked).

## Next Action
Align bundled runtime and the intended Java target, then validate a packaged launch. Do not lower the language target without checking actual Java 25 usage. No build configuration changed in this audit.
